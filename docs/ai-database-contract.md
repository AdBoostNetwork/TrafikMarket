# AI Database Contract — `traffmarket_ai`

Схема **собственной БД ИИ-помощника** `traffmarket_ai` — операционные данные помощника (история
диалогов и память пользователя). Отдельная база в контейнере `postgres`, владелец — роль
`ai_assistant`, собственное окружение миграций `ai_alembic/` (сервис `ai-migrate`), не связанное
с корневым `alembic/`.

Схема основной БД платформы — в [database-contract.md](database-contract.md); архитектура и
границы помощника — в [ai-assistant.md](ai-assistant.md).

**Живой документ.** Обновляется синхронно с каждой миграцией `ai_alembic`: и раздел миграций, и
раздел таблиц.

Вне этой БД (сознательно): история цен/метрик — в основной БД `traffmarket`; подписки на
уведомления — в основной БД и `app` (раздел Push).

---

## Роль и окружение

- База `traffmarket_ai`, владелец — роль `ai_assistant` (LOGIN, права только на эту БД).
- Создание базы и роли — идемпотентный пред-шаг сервиса `migrate` (`dockerfiles/entrypoint-migrate.sh`),
  до миграций.
- Миграции — `ai_alembic/` + `ai_alembic.ini` (`env.py` читает `AI_DATABASE_URL`), сервис `ai-migrate`.
- Приложение подключается read-write фабрикой `backend/ai_assistant/db/ai_session.py`.

---

## Миграции

### `0001_baseline`

Пустая базовая ревизия — заводит таблицу `alembic_version`. Доменных таблиц нет.

### `0002_create_dialogs_and_messages`

Создаёт таблицы `dialogs` и `messages` — история диалогов помощника. Модель — **сессии**: у
пользователя несколько разговоров, граница нового определяется по паузе неактивности (логика — в
коде, `last_message_at`). Храним только **видимые реплики** (сообщение пользователя и финальный
ответ ассистента), без tool-трейса.

### `0003_create_user_facts`

Создаёт таблицу `user_facts` — долговременная память о пользователе. Один факт = одна строка
свободного текста, привязанная к `user_id`; факты формулирует и курирует (добавляет,
переписывает или удаляет по `id`) модель. Без отметки времени, без ограничения уникальности,
без связи с диалогами.

## Таблицы

### 1 `dialogs`

Разговор (сессия) пользователя с помощником. Группирует сообщения. `last_message_at` — время
последней активности: по нему код решает, продолжить текущий разговор или начать новый.

| Столбец | Тип / атрибут | Обязательность | По умолчанию | Описание |
|---|---|---|---|---|
| `id` | `bigserial` | да | `auto` | ID разговора |
| `user_id` | `bigint` | да | `—` | Telegram ID пользователя (без FK — БД помощника отдельная) |
| `last_message_at` | `timestamptz` | да | `now()` | Время последнего сообщения (граница сессии и сортировка) |

Ограничения и индексы:

| Тип | Имя | Выражение |
|---|---|---|
| `PRIMARY KEY` | `dialogs_pkey` | `id` |
| `INDEX` | `dialogs_user_last_msg_idx` | `(user_id, last_message_at DESC)` |

### 2 `messages`

Сообщение внутри разговора. Порядок сообщений — по `id` (отдельного времени у сообщения нет).
Роль ограничена видимыми участниками диалога.

| Столбец | Тип / атрибут | Обязательность | По умолчанию | Описание |
|---|---|---|---|---|
| `id` | `bigserial` | да | `auto` | ID сообщения |
| `dialog_id` | `bigint` | да | `—` | ID разговора (FK → `dialogs.id`) |
| `role` | `varchar(16)` | да | `—` | Кто сказал: `user` или `assistant` |
| `content` | `text` | да | `—` | Текст реплики |

Ограничения и индексы:

| Тип | Имя | Выражение |
|---|---|---|
| `PRIMARY KEY` | `messages_pkey` | `id` |
| `CHECK` | `messages_role_check` | `role IN ('user', 'assistant')` |
| `FOREIGN KEY` | `messages_dialog_id_fkey` | `FOREIGN KEY (dialog_id) REFERENCES dialogs(id) ON DELETE CASCADE` |
| `INDEX` | `messages_dialog_id_idx` | `(dialog_id, id)` |

### 3 `user_facts`

Долговременная память помощника о пользователе — устойчивые факты, живущие между разговорами
(«продаёт авто-каналы», «бюджет до 300$»). Один факт — одно предложение на естественном языке;
порядок и чистоту (дубли, устаревшее) поддерживает модель, переписывая или удаляя факт по его
`id`.

| Столбец | Тип / атрибут | Обязательность | По умолчанию | Описание |
|---|---|---|---|---|
| `id` | `bigserial` | да | `auto` | ID факта (по нему модель обновляет/удаляет конкретный факт) |
| `user_id` | `bigint` | да | `—` | Telegram ID пользователя (без FK — БД помощника отдельная) |
| `content` | `text` | да | `—` | Факт одним предложением |

Ограничения и индексы:

| Тип | Имя | Выражение |
|---|---|---|
| `PRIMARY KEY` | `user_facts_pkey` | `id` |
| `INDEX` | `user_facts_user_id_idx` | `(user_id)` |
